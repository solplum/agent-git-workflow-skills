# Git Sync

+
## V2：可组合、可恢复的执行模型（优先于下文任何冲突规则）

\`git-sync\` 默认是安全的“检查与对齐建议”，不是隐含的分支重建。用户可在开发前、开发中或开发后反复调用；它不要求其他 Skill 已运行。

### 默认模式：安全同步

1. 确认当前 worktree 和 \`origin\`，只读 fetch。
2. 自动识别远端默认分支：优先 \`refs/remotes/origin/HEAD\`，其次 \`origin/main\`、\`origin/master\`；识别失败时询问，不假定 main。
3. 报告工作区脏状态、当前分支与默认分支的领先/落后关系、以及是否存在未推送 commit。
4. 当前分支已经对齐时，幂等地报告“无需操作”；不创建文件、不创建分支、不重置。
5. 工作区有改动、当前分支有独有 commit 或分叉时，只给出可选方案并停止；不得自动覆盖。

### \`--rebuild\`：显式重建模式

只有用户明确调用 \`git-sync --rebuild\` 后，才进入分类、备份与刷新流程。仍须：

- 展示将受影响的分支、目标 SHA、工作区状态、diff 统计、保留项与忽略项；
- 对要覆盖的已跟踪改动创建唯一时间戳备份分支；
- 再次获得“将当前分支重置到 <远端默认分支>”的明确确认；
- 仅随后执行 reset，并报告备份分支和恢复命令。

项目预设可继续使用 \`.codex/git-sync-profile.md\` 或当前宿主等价路径，但首次生成、更新预设或 \`.gitignore\` 时仍须先展示并确认。该预设不是默认同步的前提条件。

绝不 push，绝不 git clean，绝不删除备份分支。


## Codex 执行覆盖（优先于下文）

- 在当前 worktree 运行 `git rev-parse --show-toplevel`，并只在该 worktree 操作；先读取根目录 `AGENTS.md`（若存在）。不得影响其他 worktree、分支或仓库。
- `git fetch origin main` 是网络操作。若沙箱拦截，使用平台的受限提权请求重试同一条命令；失败即停止，不替换为其他来源或手动下载。
- 任何写入 `.codex/git-sync-profile.md` 或 `.gitignore` 的操作，必须先展示内容并取得用户确认；这些文件均为本地偏好，不应被本 skill 暂存或推送。
- `git reset --hard origin/main` 是破坏性操作。执行前必须重新显示当前分支、目标 SHA、`git status --short`、`git diff --stat` 和待保护文件清单；备份分支已创建且可用后，仍须获得一次明确的、针对“把当前 worktree 的 <branch> 重置为 origin/main”的确认。
- 备份分支名使用精确时间戳 `backup/pre-sync-YYYYMMDD-HHmmss`，先验证该名称不存在。不得自动删除任何备份分支，也不得将备份分支推送远端。
- 若已跟踪 diff 中包含 `.env`、凭据、token、私有配置或其它敏感路径，停止自动备份并请用户决定安全处理方式；`git add -u` 不得绕过这项检查。
- 操作结束后报告实际的当前 HEAD、备份分支、保留/忽略项和恢复命令；不得把预期状态当作实际状态。

从 `origin/main` 同步当前分支，安全保留本地独有文件。全程云端只读（**永不 push**）。

## 前置检查

1. 确认是 git 仓库：`git rev-parse --is-inside-work-tree`，非 git 仓库 → 报错退出。
2. 确认 remote 存在：`git remote -v` 包含 `origin`，否则提示配置。
3. 确认当前分支：`git branch --show-current`。
   - 若当前分支是 `main` → 走快进（`git merge --ff-only origin/main`），不执行重建流程。

## 工作流

### ① fetch 云端主干（只读）

```bash
git fetch origin main
```

失败 → 停止，报告错误，不动工作区。

### ② 读取 / 生成预设文件

预设路径：`.codex/git-sync-profile.md`（**本地专属，加入 `.gitignore`，不提交云端**）

- **存在** → 读取，作为分类依据。
- **不存在（首次）** → **完整盘点仓库**生成预设，展示给用户微调确认后写入。

**生成规范（完整盘点，不遗漏任何类）：**
1. 列仓库顶层目录，读各模块作用（每项一句话，≤20 字）。
2. 三组命令补齐三类信息：
   - `git status --short` → 未跟踪/已修改（本地独有 + 重叠候选）
   - `git status --ignored --short` → 被忽略的缓存/构建/运行态（**必须跑，靠固定清单会漏**）
   - `git ls-tree` 对比主干 → 主干独有/重叠
3. 每个路径**显式标注处理方式**（主干 / 保留 / 忽略），不要只列目录名。
4. 按下方模板生成完整预设 → 用户确认 → 写入。

**预设文件模板：**
```markdown
# Git-Sync 项目预设
## 项目脉络
- <目录> → <作用>（处理：主干 / 保留 / 忽略）
## 保留
- <路径> → <说明>
## 忽略
- <路径> → <是什么>
## 规则偏好
- 重叠文件 → 用主干
```

### ③ 增量检测

对比预设与当前未跟踪文件：找出预设没见过的本地文件 → 提示用户是否加入预设。

### ④ 四类文件分类

计算"本地独有"文件集（当前分支 `HEAD` 与 `origin/main` 的差集），逐一分类：

| 类别 | 默认策略 |
|------|---------|
| 文档 / 配置 / 素材 | **保留**（不逐项问） |
| 代码（源码/脚本） | **逐项读作用后询问保留与否** |
| 工具缓存 | 忽略 + 补进 `.gitignore` |
| 主干独有 / 重叠 | 用主干版本 |

**缓存清单**（命中即忽略）：`.codex/` `.claude/` `.agents/` `.codegraph/` `.superpowers/` `__pycache__/` `node_modules/` `target/` `build/` `dist/` `*.log` `login.json` 及锁文件。

**注意**：固定清单只是起点。运行时用 `git status --ignored --short` 找出所有已被忽略的缓存/构建/运行态（如 `**/target/`、`.dart_tool/`、`.env`、`local.properties`、`data/`、`logs/`、`*.zip` 缓存），逐一归入忽略类并写入预设。敏感文件（`.env`、凭据、token 文件）一律忽略。

**本地独有代码的询问格式**（读文件头/README/目录结构判断，每项 ≤ 一句话）：

```
⚙ 本地独有代码（N 项）
1. <路径> —— <一句话作用>
   保留? [y/n]
（可全 y / 全 n / 逐项选）
```

### ⑤ 自动备份（不 push）

**原则**：只备份"会被重建覆盖"的**已跟踪修改**（重叠文件本地旧版、本地修改的配置文件等）。**保留类未跟踪文件（如 docs/）绝不 commit**——它们作为未跟踪文件在重建后天然存活，且本就不该进 git。

```bash
# 只暂存已跟踪文件的修改/删除，不含未跟踪文件（避免误提交 docs/ 等保留文件）
git add -u
git commit -m "backup: pre-sync WIP <YYYY-MM-DD>"
git branch backup/pre-sync-<YYYY-MM-DD>
```

- `git add -u`：只暂存**已跟踪文件**的修改/删除，**未跟踪文件自动排除**。
- 禁用 `git add -A` / `git add .`——会把保留类未跟踪文件（docs/）误提交进 git。
- 若备份后分支恰好无内容可提交（`nothing to commit`）→ 说明无已跟踪修改需保护，跳过 commit，仅在有内容时打备份分支。

### ⑥ 一键确认 + 当前分支直接刷新到主干（不开新分支）

展示保留清单 → 用户确认 → **在当前分支上直接刷新到主干**：

```bash
# 备份已完成 → 刷新当前分支到主干（未跟踪保留文件 docs/ 等天然存活）
git reset --hard origin/main
# 从备份取回选定的保留项（如 .gitignore 防护规则）
git checkout backup/pre-sync-<YYYY-MM-DD> -- <选定的保留文件>
```

- **不开新分支**：直接刷新当前分支，当前分支就是新工作台。
- **注意**：当前分支上**已提交但主干没有的本地提交会被丢弃**——刷新前必须经用户确认接受（备份分支已兜底，可恢复）。
- 未跟踪保留文件（如 docs/）`reset --hard` **不会动**，天然存活。
- 确认后发现问题 → 从 `backup/pre-sync-<日期>` 恢复。

### 报告

输出：同步结果 + 保留的文件列表 + 恢复命令（从 `backup/pre-sync-<日期>` 取回）。
- **备份分支确认无误后可按需删除**：`git branch -D backup/pre-sync-<日期>`。删除前必须确认：保留文件（docs/ 等）都在、主干代码正常。
- 旧备份清理：`git branch -D backup/pre-sync-<旧日期>`，仅用户确认后执行。

## 安全铁律

1. **永不 push 云端**——云端只做 fetch。
2. **永不 `git clean`**；`git reset --hard` **仅允许在备份完成 + 用户确认后**用于刷新当前分支（步骤⑥），未备份前禁用。
3. 任何覆盖前**先备份**，恢复路径永久保留。
4. 工作区 dirty 时不静默继续——先说明，让用户选保护方式（commit / stash / stop）。
5. 所有"将被丢弃"的东西留备份分支，报告给出恢复命令。

## 边界与错误处理

- 非 git 仓库 → 报错退出，不动任何文件。
- 当前分支 == `main` → fast-forward，不重建。
- 只同步**当前分支**，不动其他 worktree。
- 遇冲突 → 停止 + 报告冲突文件 + 给下一步命令，不自动解决。
- fetch 失败 → 停止，不动工作区。
- skill 只做 git 操作，不修改用户文件内容（读代码判断作用除外）。
